# Domain Docs

This repo uses a single-context layout.

- Before exploring the codebase, read the root `GLOSSARY.md` and relevant ADRs under `docs/adr/` if present.
- Use glossary terms in issues, proposals, and tests. Record terminology gaps for `/domain-modeling`.
- If a proposal conflicts with an ADR, identify the ADR and explain why the decision should be revisited.

The domain-modeling skill creates the glossary and ADRs as terms and decisions are settled.
